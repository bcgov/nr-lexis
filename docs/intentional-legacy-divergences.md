# Intentional legacy divergences

Modern LEXIS normally preserves functional parity with legacy. Intentional modernizations, security
controls, and approved retirements use the searchable code marker
`INTENTIONAL_LEGACY_DIVERGENCE(<ID>)` and are recorded here so they are not mistaken for parity
defects.

| ID                                      | Modern behaviour                                                                                                                                                                                                             | Reason                                                                                                                        |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `SEARCH_STATE_PERSISTENCE`              | Applied search filters, sorting, and paging survive in-app navigation. Logout, session expiry, login, and organization changes clear the saved state. A fresh authenticated visit shows no results until Search is selected. | UI review request; legacy does not retain search state across page navigation.                                                |
| `CLEAR_ALL_RESETS_SEARCH`               | Clear all resets the filters and returns table-backed search pages to their initial state with no results table. It does not submit an unfiltered search. | Business and UI review direction to avoid distracting users with results that no longer correspond to visible filter selections. |
| `CONTEXTUAL_RETURN_NAVIGATION`           | A detail page one level below its parent exposes one deterministic named Back link; deeper detail navigation exposes a Carbon breadcrumb of accessible ancestors. Search, review, summary, and nested-detail navigation record the actual originating target and preserve its exact URL and router state; direct or bookmarked detail visits use the canonical accessible parent or role default. | Heartwood navigation requirement; legacy exposes display-only section breadcrumbs and fixed search or cancel targets, with no originating-list or query-state contract. |
| `RESPONSIVE_SIDE_NAVIGATION`             | Side navigation remains available at narrow widths as a collapsed icon rail that can be temporarily expanded. Its narrow-screen state is independent of the persisted desktop collapsed or expanded preference. | Heartwood navigation requirement; legacy exposes a fixed-width text menu with no responsive collapsed state or saved navigation preference. |
| `NAVIGATION_MENU_CONTRACT`               | Search links are labelled Application search, Exemption search, Offer search, and Permit search; Federal uses Application search; Admin navigation and page headings use Multiplication Factor and Non-appraised Sec.3 FIL%. A new session expands Provincial and collapses Federal, Reports, and Admin. Provincial Submitters do not receive Federal, Reports, or Admin sections. | Business-approved menu terminology, density, and role visibility; regression passes must not restore the legacy labels or expansion behaviour. |
| `DETAIL_VIEW_EDIT_MODES`                | Authorized detail pages open in view mode and expose explicit Edit and Cancel actions.                                                                                                                                       | UI review request to follow the modern design pattern instead of legacy's always-editable presentation.                       |
| `BCEID_APPLICATION_EDIT_CONTRACT`       | Authorized BCeID application edits remain available through the modern edit flow without depending on optional legacy-only status or remarks fields. A legacy client-side null dereference for those omitted fields is not reproduced.                                                                 | Preserve the authorized application-edit capability while treating the legacy missing-field failure as a defect, not as a modern functional contract.                                      |
| `PACKAGE_FIRST_ITEMS_WORKFLOW`          | Modern package-backed Items workflows hide dependent Package Details and Summary of Scale content until a package exists. Where creation is authorized, package creation is the primary action; read-only views retain only the package empty state. Unsaved application create explains and enforces the save-first prerequisite. Existing-package views use the business term Summary of Scale and retain multi-package support. | Business-confirmed modernization. A package is required before Summary of Scale entry, package creation is primary for the common one-package surplus-test application, and Summary of Scale is the correct term for scaler or third-party summary data. Legacy instead renders empty dependent sections before the prerequisite action. |
| `EXEMPTION_CREATE_SAVE_FIRST`           | Exemption creation presents application linking and exemption details in one save form. Owner data is derived from the linked applications; documents, permits, and fees are managed from the saved exemption detail page. | The dependent workflows require a persisted exemption number. Reproducing legacy's full detail-tab shell before save would expose empty or nonfunctional sections. |
| `ADMIN_PAGE_RETIREMENT`                 | The Users & Access page and its IDIR lookup API are not exposed. Other administration workflows remain available.                                                                                                            | Business-requested retirement; the legacy administration capability is no longer required.                                    |
| `ADMINISTRATOR_SUPER_ROLE`              | Modern Administrator can perform every active modern LEXIS function, including Ministerial exemption approval, Approved Exemption printing, and application-submission import. Retired report screens remain denied as documented in `RETIRED_REPORT_SCREENS`. | Modern Administrator is intentionally the all-access role for active functions.                                                |
| `MULTI_FILE_UPLOAD_QUEUE`               | Application submission and document workflows can queue, validate, review, and submit multiple files.                                                                                                                        | Modern workflow improvement; legacy upload pop-ups accepted one `formFile`.                                                   |
| `RTM_AMV_SPREADSHEET_UPLOAD`            | Administrators maintain AMV values through the XLSX validation, review, and atomic upload workflow. The former editable-grid route redirects to that workbook workflow, which retains the existing schema and synchronization trigger. | Provides the approved workbook-only AMV experience while preserving the authoritative AMV data contract.                       |
| `CLAMAV_UPLOAD_SCANNING`                | Deployed uploads are scanned through the shared ClamAV service before persistence. Infected files and unavailable scans are rejected.                                                                                        | Modern security control; legacy upload actions did not perform malware scanning.                                              |
| `INDIGENOUS_RESERVE_MODULE_RETIREMENT`  | Legacy Indian/Indigenous Reserve search, create, detail, API, authorization-action, and report-jurisdiction surfaces are not exposed.                                                                                        | Intentional retirement of the Indigenous Reserve module.                                                                      |
| `ADVERTISING_REPORT_VARIANT_RETIREMENT` | The `generateIndustryPDF` and `generateIndustryCSV` shortcuts and legacy root `biweeklyListing` routes are retired. The filtered Advertising List remains and exposes PDF/CSV as an output-format choice.                    | Consolidates duplicate legacy shortcuts into one maintained report workflow.                                                  |
| `RETIRED_REPORT_SCREENS`                | Modern LEXIS excludes Application Report, Create TEAC Package, Exemptions Report, and Fees Report from navigation, redirects their UI routes, and denies their modern and legacy-compatible API routes. Authorized users may still access the historical screens in the separate legacy application. | Business-confirmed retirement. |
| `NOTIFICATION_MODULE_ADDITION`          | Authenticated users can read active, role-targeted operational notifications. Authorized administrators can manage the notification schedule and content.                                                                    | Adds an in-application operations channel that does not exist in legacy.                                                      |
| `SEARCH_FILTER_EXPANSION`               | Provincial application and exemption searches add received/approval date ranges, and permit search visibly exposes the invoice-number criterion.                                                                             | Exposes useful criteria supported by the modern query contract; the legacy screens did not show them.                         |
| `HISTORICAL_ORG_UNIT_SEARCH_VISIBILITY` | An exact modern exemption search can return a historical or inactive organizational-unit record, such as exemption `12-8238`, when the record is otherwise authorized and directly identified.                                                                                              | Preserve exact-record discoverability for historical data; legacy's active-region default can omit records belonging to an older organizational unit and is not an intentional modern search constraint. |
| `FAM_STAFF_GLOBAL_DATA_SCOPE`           | IDIR Administrators, Application Approvers, Exemption Approvers, and Read Only users provisioned as staff identities have global record scope within the actions granted to their roles. Zone and region selections are defaults and filters, not authorization boundaries. Provincial Submitter identities remain separately scoped to records associated with their selected FAM forest client. | Replaces legacy WebADE selected-organization regional scoping with the approved FAM role-and-client authorization model. LEXIS enforces staff-only IDIR roles and client-scoped Provincial Submitter-only BCeID Business roles during Cognito token conversion; FAM should also reject incompatible assignments at provisioning time. |
| `FEDERAL_DETAIL_APPROVAL_TRANSITION`    | Authorized federal detail users can approve a `NEW` or `PND` application from the detail page. The backend applies the shared Application Review readiness validation before changing the status to `APP`.                  | Keeps the preferred detail-page action without bypassing the legacy approval domain gate.                                     |
| `ASYNC_WORKFLOW_EMAIL_DELIVERY`         | Workflow mutations complete when their business transaction commits and queue any resulting email for best-effort asynchronous delivery after commit. A successful workflow response confirms the mutation, not SMTP delivery; delivery failures are logged and metered. | Prevents SMTP latency or failure from rolling back or delaying an already committed business operation.                       |
| `CANONICAL_SEARCH_RESULTS`              | Provincial exemption and permit searches return one row per exemption or permit, and counts use the same canonical candidate set. Joined application, region, and scale rows do not duplicate results or multiply balances. | Avoids legacy join fan-out that can duplicate exemptions, inflate permit counts, and multiply permit-volume balance values.    |
| `PERMIT_INVOICE_VISIBILITY`             | Permit detail includes an Invoices tab with invoice rows and authorized invoice-document actions.                                                                                                                            | Makes the modern invoice workflow and its authoritative data visible from the permit.                                         |
| `PERMIT_APPROVAL_EMAIL_RESEND`          | Eligible permit reviewers expose an Email approval action that can preview and resend the approval message.                                                                                                                  | Provides an operational recovery action after the original permit approval workflow without granting approval-email capability to Provincial Submitters.   |
| `EXPIRED_DOCUMENT_MAINTENANCE`          | Authorized Application Approvers, Provincial Submitters, and Administrators can add and delete direct application and permit documents after the record expires. All other expired-record changes remain locked, and invoice documents remain active-permit-only.                           | Business-requested exception so reconciliation documents received after expiry can still be maintained.                       |
| `SAFE_EXEMPTION_INITIAL_STATUS`         | Ministerial exemptions are created as `NEW`; OIC and Blanket OIC exemptions are created as `ACT`. The API rejects a mismatched initial status before persistence.                                                            | Prevents invalid or partially activated exemptions that legacy's user-selectable initial status allowed.                      |
| `AUTHORITATIVE_CLIENT_LOCATION_LOOKUP`  | Client contact details are loaded using the client and persisted location code together.                                                                                                                                     | Avoids a legacy display defect that can show contact data from a different/default client location.                           |
| `COMPLETE_SHIPPING_COUNTRY_OPTIONS`     | Federal and permit shipping details expose and resolve every active country reference code, including persisted values outside legacy's initial short list.                                                                  | Avoids a legacy display defect where a valid country such as `AD` renders blank after the short-list selector is initialized. |
| `PROVINCIAL_SUMMARY_CLIENT_SCOPE`       | Provincial Summary remains a client-scoped BCeID dashboard for Provincial Submitters. My Exemptions includes ordinary Ministerial and OIC exemptions associated with the selected FAM forest client; non-client-specific Blanket OIC exemptions remain globally visible. Results are canonical, with one row per exemption. Summary is not exposed to Read Only staff, who view the underlying records through the provincial search tables. | Legacy Read Only was unfinished and its clientless Summary is not authoritative for staff access. Legacy BCeID Summary can also omit client-linked OIC and Blanket OIC records that its Exemption Search can return; modern preserves selected-client ownership for ordinary exemptions and the established global scope for Blanket OIC. |

The Advertising List change retired two legacy shortcuts, not two complete reports. The Approved
Exemption and Permit printable reports remain available from their respective detail pages.

Business direction confirms the retirement of Application Report, Create TEAC Package, Exemptions
Report, and Fees Report.

Keep markers next to the controlling code rather than on every consuming component.
