# Intentional legacy divergences

Modern LEXIS normally preserves functional parity with legacy. Intentional modernizations, security
controls, and approved retirements use the searchable code marker
`INTENTIONAL_LEGACY_DIVERGENCE(<ID>)` and are recorded here so they are not mistaken for parity
defects.

Only observable differences in supported inputs, user workflow, authorization, persistence, or
integration behaviour belong in the divergence table. Refactors, duplicated service-boundary
enforcement, and early validation of existing legacy or database constraints are parity work.
Stored-procedure replacements are listed separately below as an implementation inventory.

The business-approved 100-row default applies only to IDIR Application Review, which also offers
150/200-row options. All other search pages retain the legacy 10-row default; the general Search
Results wording in Confluence does not expand the 100-row default to those pages.

## Detail-flow functional boundaries

Visual alignment preserves existing role, lifecycle and transaction contracts:

- Active exemption approved volume remains locked, as in legacy. Approval dates are established by
  approval; switching a new draft to Ministerial clears a date entered for OIC or Blanket OIC.
- Ministerial permit application attachments retain their separate explicit Add operation. A general
  section Save does not silently attach selected applications or bypass its relationship checks.
- Saved permit Agent assignments remain subject to the current ownership restrictions. Editable
  fields are not enabled merely because a design depicts an input.
- BOIC Add scale uses a drawer with Cancel and Save, matching the legacy dialog's separate save
  boundary. It captures the selected package and retains validation, record-version and in-flight
  guards. Cancel discards only the unsaved scale draft, asking first when it has values.
- Ministerial scale totals remain application-scale quantities; BOIC completed totals remain
  completed-permit quantities. Labels follow the quantity actually returned by the service.
- Application/exemption document tables use their reviewed drawer flow. Permit uploads retain the
  existing validation/review submission flow; their empty/table presentation uses the shared layout.
